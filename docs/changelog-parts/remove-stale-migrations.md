## Old conversions removed from three modules / Anciennes conversions retirées de trois modules

*EN: three modules no longer carry the code that converted data from their first versions, and Live status stops running a useless hourly task. Nothing to set up. A site that is still on a very old version of one of these modules updates through an intermediate version, by itself. Modules touched: Contacts 2.5.0, Partnerships 2.2.0, Announcement story 2.9.0, Live status 1.4.4.*
*FR : trois modules n'embarquent plus le code qui convertissait les données de leurs premières versions, et Statut du live arrête une tâche horaire inutile. Rien à régler. Un site encore sur une très ancienne version de l'un de ces modules passe tout seul par une version intermédiaire. Modules touchés : Contacts 2.5.0, Partenariats 2.2.0, Story d'annonce 2.9.0, Statut du live 1.4.4.*

### What changes for you / Ce qui change pour vous

- **EN: Nothing changes on a site that is up to date.** Your contacts, partnerships and announcement stories are untouched. Older sites (Contacts 1.x, Partnerships 1.x, Announcement story 1.x) are carried through the last version that still converted them (tag `v1.50.0`) when they update from the Catalogue, one version after the other, as before.
- **FR : rien ne change sur un site à jour.** Vos contacts, partenariats et stories d'annonce ne sont pas touchés. Les sites plus anciens (Contacts 1.x, Partenariats 1.x, Story d'annonce 1.x) passent par la dernière version qui les convertissait encore (étiquette `v1.50.0`) quand ils se mettent à jour depuis le Catalogue, une version après l'autre, comme avant.
- **EN: If a module is set aside with "install an intermediate version first".** It means its data was too old to be converted by this version and nothing was changed. Install the module again at the tag `v1.50.0`, let it start, then update. The list of floors is in `docs/MIGRATIONS.md`.
- **FR : si un module est mis de côté avec « installez d'abord une version intermédiaire ».** Ses données étaient trop anciennes pour cette version et rien n'a été modifié. Réinstallez le module à l'étiquette `v1.50.0`, laissez-le démarrer, puis mettez-le à jour. La liste des planchers est dans `docs/MIGRATIONS.md`.
- **EN: Old copies are shown, never lost.** What the old conversions left in the storage (Partnerships: `contacts`, `legacyContacts`, `meta`; Announcement story: the version 1 co-streamer list) stays where it is and is counted on the Upkeep page. The safety copy of Partnerships and the version 1 list of Announcement story can now be deleted from that page, in advanced mode, when you decide to. Announcement story no longer proposes that old list as "people kept here", and its readable backup no longer contains `costreamers.csv`.
- **FR : les anciennes copies sont montrées, jamais perdues.** Ce que les anciennes conversions ont laissé dans le stockage (Partenariats : `contacts`, `legacyContacts`, `meta` ; Story d'annonce : l'ancienne liste de co-streamers) reste en place et est comptée par la page Entretien. La copie de sécurité de Partenariats et l'ancienne liste de Story d'annonce peuvent maintenant être supprimées depuis cette page, en mode avancé, quand vous le décidez. Story d'annonce ne propose plus cette ancienne liste comme « personnes gardées ici », et sa sauvegarde lisible ne contient plus `costreamers.csv`.
- **EN: Live status no longer runs a task every hour.** The old Twitch settings are handed over to My Twitch channel when the module updates, and again whenever you open the Live status page. Nothing is deleted without being confirmed by My Twitch channel.
- **FR : Statut du live ne lance plus de tâche toutes les heures.** Les anciens réglages Twitch sont repris par Ma Chaîne Twitch à la mise à jour du module, et de nouveau chaque fois que vous ouvrez la page de Statut du live. Rien n'est effacé sans la confirmation de Ma Chaîne Twitch.

### For developers

- **Rule written down: `docs/MIGRATIONS.md`.** The support floor of a module is its `dataFloor` plus a bridge tag (the last release with the conversion, never deleted). When a conversion may go, what the removal release must declare, leftovers in `legacyCollections` (and `inertLegacyCollections` for a copy the module never reads again), and the two-step removal of secret hand-overs. New test `module-data-floor`: every `dataFloor` above 1 is in the table, its bridge tag exists and still carries the conversion.
- **Contacts 2.5.0** (`dataFloor` 2): `migrate.mjs` and `tests/contacts-migration.test.mjs` removed (their subject is gone), `touchStamp` and `storeHasKeys` (used only by it) removed from `data.mjs`. `migrations[2]` stays as an empty marker: the kit rule `data.version` wants one entry per `dataVersion` above 1, and it never runs on data already in version 2.
- **Partnerships 2.2.0** (`dataFloor` 2): `migrate.mjs` removed, the admin notices of the reprise and the `mig*` / `check_*` texts removed in both languages, `legacyCollections` kept, `inertLegacyCollections` added for `legacyContacts`. `tests/partnerships-migration.test.mjs` replaced by `tests/partnerships-data-floor.test.mjs` (manifest, leftovers untouched, no merge screen).
- **Announcement story 2.9.0** (`dataFloor` 2): `migrate.mjs` removed, `readLegacy` / `removeLegacy` / `readPickable` and the "earlier list" tag and banner removed, `timing.migrateMs` and `LIMITS.savedCostreamers` removed, `story_costreamers` declared in `legacyCollections` and `inertLegacyCollections`. The five migration tests of `stream-story-contacts` and the one of `hang-stream-story` are removed (subject gone) and replaced by one test of the new state; the update test starts from the 2.4.0 fixture only: `tests/fixtures/stream-story-2.1.0` and `2.3.0` are removed.
- **Live status 1.4.4**: the `adopt` task (every 60 minutes) is removed; `adoptLegacy` also runs when the admin page is opened. Step 1 of the removal of this secret hand-over; step 2 (delete the hand-over) comes in a following release, together with the other hand-overs (Planning, YouTube channel, Twitch channel, Game suggestions).
- **Not removed, on purpose**: the Twitch raid 2.0 conversion (its last steps are done by a person and its progress lives outside `dataVersion`), the Twitch bot timers conversion, `legacyKey` of stream events, the countdown `legacyHead`, the "legacy" actions of the bot, and the fallback stylesheets "before core 0.6.6" of Audience and Twitch raid (their `minCore` is still below 0.6.6).
