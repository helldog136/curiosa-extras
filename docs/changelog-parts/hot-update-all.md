## Mises à jour à chaud : une protection automatique pour tous les modules

## Améliorations
- Mettre à jour un module sans redémarrer le site est maintenant vérifié automatiquement pour chacun des modules du dépôt. Cela évite qu'une mise à jour laisse un module « impossible à charger », comme c'était arrivé à Statut du live.
- Cinq modules avaient le même défaut caché et sont corrigés avant qu'il se produise : Questions fréquentes (1.0.1), Contacts (2.2.2), Mur des remerciements (1.0.1), Assistant maison (1.0.1) et Autres plateformes (1.0.1). Le Labyrinthe en overlay (1.1.1) recharge aussi son tracé aléatoire. Rien ne change pour vous : mêmes pages, mêmes réglages, mêmes données.

## Pour les développeurs
- Nouveau test générique `tests/hot-update-all.test.mjs` (aides : `tests/helpers/hotUpdate.mjs`, règle expliquée dans `docs/HOT-UPDATE.md`). Pour chaque module : (1) analyse du code, sans l'exécuter, des fichiers que le serveur charge à partir de `main` : tout `import … from "./x"` / `export … from "./x"` / `import "./x"` relatif statique est refusé, et tout `import(…)` relatif doit porter la version (`${v}`, `${q}` ou `+ q`) ; liste blanche explicite `ALLOWED_STATIC` (une seule entrée : `maze-overlay/web/generate.js`, fichier partagé avec le navigateur) et `BROWSER_ONLY` (fichiers `.mjs` envoyés au navigateur) ; (2) pour les 34 modules à plusieurs fichiers serveur, rejeu de la mise à jour N-1 → N dans un seul processus : version de la dernière étiquette où la version du module diffère (`git archive`), chargée avec `?v=ancien` et utilisée avec le faux contexte de `testsupport` (sondes `runScenario`), puis fichiers remplacés dans le même dossier, version courante chargée avec `?v=nouveau` et utilisée avec l'état créé ; un témoin (même version, dossier neuf) donne la liste des fichiers qui doivent être rechargés ; échec si un fichier reste à l'ancienne version, est évalué sans `?v=`, ou si une exception apparaît que le témoin n'a pas.
- Sans historique git (aucune étiquette), le rejeu se fait sur la version courante contre elle-même et un test « historique git disponible » est sauté avec sa raison ; `HOT_UPDATE_REQUIRE_HISTORY=1` le transforme en échec. `.github/workflows/ci.yml` : `fetch-depth: 0` et cette variable.
- Correctifs : `faq` 1.0.1 (tous les fichiers serveur), `contacts` 2.2.2 (`book`, `csv`, `data`, `migrate`, `subjects`, `ui` ; 2.2.2 = aussi le test d'import sans horloge), `thanks-wall` 1.0.1 (`data.mjs`), `home-assistant` 1.0.1 (`moderation.mjs`), `platform-links` 1.0.1 (`index.mjs`) : `await import(\`./x.mjs${v}\`)`. `maze-overlay` 1.1.1 : `web/generate.js` importé avec la version. Les tests qui épinglent ces versions (`contacts-v2`, `home-assistant`, `maze-overlay`) sont mis à jour.
